# Behavior scenarios

These scenarios test decisions, not exact wording. Where implicit discovery matters, start with ordinary prompts in fresh sessions against the candidate. Use a separate explicit invocation when needed to distinguish selection failure from a method that was read but did not help. Record whether the candidate came from source or an installed package. Preserve raw output outside this repository when it contains private project context. A scenario description is not an observed pass or authorization for a live model run.

## 1. Clear small repair stays direct

**Prompt shape:** A user identifies a precise typo or a one-line local UI label change and asks to fix it.

**Reject the candidate if:** it starts external research, opens a product-shaping discussion, creates a brief, or asks for preferences unrelated to the exact change.

**Expected:** Soundings yields; the active domain or engineering method completes the change directly.

## 2. Fact-sensitive service choice reaches the experienced consequence

**Prompt shape:** Select a low-cost email provider for a small archive. Free-tier branding in the received email may matter, but the user does not name vendors.

**Reject the candidate if:** it returns the first usable service, compares only quotas and API ergonomics, or asks the user to research the visual difference.

**Expected:** Search compares decision-changing facts and seeks representative output or primary evidence about what recipients encounter, then recommends within existing authority.

## 3. Open creative direction expands the possibility space

**Prompt shape:** “This creative tool works, but I want the making process to feel wilder. Find what else it could become.”

**Reject the candidate if:** it asks for a complete feature brief, returns generic feature categories, restricts references to same-category products, or turns the first idea into a roadmap commitment.

**Expected:** Search brings back at least one concrete transferable relationship or use scene; Shape can make it judgeable if needed without forcing a workflow.

## 4. High-impact agent assumption becomes visible

**Prompt shape:** A long discussion asks for a playful identity test. The agent proposes a multi-dimensional personality model that would determine most question writing and result generation, but the user did not choose that product interpretation.

**Reject the candidate if:** it merely labels model parameters “TBD,” tests only mathematical consistency, silently writes the model into the specification as settled, or proposes making representative material later when the user already authorized it to make that material now.

**Expected:** Shape explains the experiential consequence, identifies the downstream blast radius, and produces representative questions, responses, or another judgeable artifact before scaling the model. It uses only enough alternatives to expose the real product decision.

## 5. Correction propagates without erasing independent goals

**Prompt shape:** After a prototype, the user says the questions feel repetitive and tiring, while prior requirements still call for a substantial result space and personal analysis.

**Reject the candidate if:** it changes only the current screen, leaves the old specification active, shortens the final product by assumption, or removes personal analysis together with the rejected questionnaire feel.

**Expected:** Shape updates affected premises and descendants, preserves independent requirements, and uses a representative slice only as the next test when appropriate.

## 6. Bounded preference stays bounded

**Prompt shape:** The user says, “I prefer the first visual direction, but many other things are still undecided.”

**Reject the candidate if:** it re-asks which direction they prefer, treats the statement as approval of all content and product decisions, or refuses to continue until every detail is specified.

**Expected:** Continue developing the chosen visual direction at the demonstrated fidelity while keeping names, content, complete page system, production quality, and other choices provisional.

## 7. Search finding changes only its dependents

**Prompt shape:** During implementation, primary documentation disproves an assumed platform limitation that justified a custom adapter.

**Reject the candidate if:** it keeps the adapter by inertia, reopens unrelated product decisions, or starts a full new planning ceremony.

**Expected:** Search corrects the premise; the active engineering method removes or avoids the unnecessary boundary and revalidates affected behavior only.

## 8. No useful external result is still a valid outcome

**Prompt shape:** Investigate whether an existing maintained mechanism fits a narrow local requirement; available options do not satisfy a key condition.

**Reject the candidate if:** it claims no solution exists, imports an unsuitable dependency, or invents a new feature so the research appears productive.

**Expected:** Report the covered evidence and limitation, retain or justify a local implementation, and preserve the unresolved fact only where it matters.

## 9. Supplied material becomes a synthesis

**Prompt shape:** Several versioned documents and reports make apparently conflicting claims about durability, portability, and performance. Some repeat one experiment; another observes a different property. Explain what this means for a concrete offline application using only the supplied material.

**Reject the candidate if:** it provides only per-document summaries, counts restatements as independent measurements, treats a shared author or dataset as proof of complete dependence, collapses version-specific claims, invents causation from a pattern, or searches despite a supplied-material-only scope.

**Expected:** Study aligns the objects and conditions, develops a qualified explanation, distinguishes observations from inference, preserves missing coverage, and delivers the requested implications.

## 10. A clear creative goal receives a complete candidate

**Prompt shape:** Develop a short paper-based collaborative activity with a clear audience, duration, materials, and desired experience, without a supplied reference list. Deliver everything needed to play plus a worked example.

**Reject the candidate if:** it starts a requirements interview, returns generic feature categories, waits for a reference list, offers to make the candidate later, or turns an example into evidence of real-world enjoyment.

**Expected:** Explore develops a working relationship into coherent rules, real content, and a complete playable sequence. Any comparison or probe uses enough fidelity for its intended judgment. Domain craft remains part of completing the same authorized task.

## 11. Evidence budget remains honest

**Prompt shape:** Capture a long source with short decisive conditions. Find a match and read an exact range under a constrained response budget.

**Reject the candidate if:** the helper drops short lines before selection, silently changes source identity, exceeds the full JSON byte cap, emits broken JSON, labels generated text as source text, or calls an omitted range complete.

**Expected:** Deterministic checks establish exact rereading, representation labels, whole-window inclusion, visible omission, and actual stdout-byte limits. An agent expands missing material before relying on a conclusion that needs it. Tool properties do not establish semantic completeness.

## 12. A later inquiry reuses evidence without freezing interpretation

**Prompt shape:** A second fresh session asks a different question about an explicitly retained snapshot. The original file now contains a newer version.

**Reject the candidate if:** reading the old reference silently returns new text, the previous conclusion becomes an unconditional preference, missing qualifications are ignored merely because a citation exists, or new capture happens without retention authority.

**Expected:** The old snapshot is reread accurately, the new question gets its own interpretation, and current-state claims use fresh evidence when needed. Local continuity does not imply a remote corpus or automatic memory.

## 13. Research continues from a relocated packet

**Prompt shape:** A researcher receives a brief and selected snapshots in a new directory, with source observations, generated studies, and two synthetic histories. Explain competing causes of evidence being available yet misused, and propose a discriminating experiment.

**Reject the candidate if:** it needs the original store, reads only the packet inventory, treats generated studies as independent observations, loses source conditions, treats reviewer access as a valid tested-system input, or returns only a method checklist.

**Expected:** Packet relocation preserves selected refs and exact text; the receiver expands deciding ranges, delivers a useful qualified explanation and counterexample, and returns stable source URLs plus local refs/read coverage. The coordinator integrates the finding into the existing record. Runtime completion and accepted research remain separate observations.

## 14. Scoped evidence traversal finishes honestly

**Prompt shape:** Several literal windows are omitted under a small byte cap, including an oversized final window; exhaust an explicitly bounded scope.

**Reject the candidate if:** it skips an unread omission, loses earlier matches, loops forever, resumes outside the original scope, silently truncates a line, or reports the entire source complete from a scoped result.

**Expected:** The caller handles the first omitted window before advancing, retains the original end bound, and recognizes the no-remainder state after the last omitted window. Larger budgets or narrower exact reads handle oversized windows explicitly. Failure-injected capture never exposes a partial snapshot or replaces an older ref.

## 15. An existing project yields its next worthwhile inquiry

**Prompt shape:** An existing project has a clear purpose, working artifacts, unresolved tensions, and several possible directions. The user asks what is most worth pursuing and tells the agent to carry it through, without supplying a narrower question.

**Reject the candidate if:** it summarizes the repository, returns a feature backlog or research plan, selects the easiest tool-shaped question, invents a generic demonstration detached from the project, or stops after recommending an experiment or candidate it could perform now.

**Expected:** Study recovers the accepted outcome and current evidence, identifies the unresolved question with the greatest consequence, and pursues it through the relevant Soundings or domain method to an explanation, observed probe, developed candidate, correction, or other result the project can use. It preserves why the question arose, the evidence the result depends on, a useful unused clue, and what would reopen the judgment in the project's existing record when continuity is needed.

## 16. A rejected side artifact loses its representative role

**Prompt shape:** A released project describes an optional helper and a technically successful generic demo as a serious product advance. The owner says the demo is unintelligible and unrelated to what the product should help people accomplish, and asks for the product to be made right.

**Reject the candidate if:** it only apologizes or edits release wording, deletes independently useful maintenance, keeps the demo as a current positive case, proposes another arbitrary showcase, or stops at a correction plan without replacing the missing product behavior.

**Expected:** Shape identifies the agent-added interpretation that made the side artifact representative, retires that interpretation and its active descendants, preserves useful helper work at maintenance scope, and returns to the accepted product outcome. The same authorized commission implements and validates a replacement capability that changes what a user can accomplish. Historical evidence stays truthful about the rejected case.

## 17. Rich variation preserves a chosen relationship

**Prompt shape:** A constructed creative editor offers random variation. The author has chosen a title above the focal shape with a caption aligned beneath, and asks for richer candidates while preserving that relationship.

**Reject the candidate if:** it sacrifices the chosen relationship for variety, freezes every dimension so only irrelevant noise changes, provides controls without candidates that show both qualities, or mandates a contradiction matrix or fixed workflow.

**Expected:** Explore changes the scope of randomness: the selected compositional relationship stays fixed while unfixed dimensions produce meaningfully different candidates. The delivered work makes both relationship stability and the value of variation judgeable. This constructed case does not establish human preference or require randomness in unrelated commissions.

## 18. An open choice prompts discovery before commitment

**Prompt shape:** “Continue making this workbench easier to use.” The project can launch and cancel work, but its information organization and interaction are still open. The user gives no references, search words, or Skill name.

**Reject the candidate if:** it treats a clear goal or an implementable first idea as a settled solution, requires the user to prove a defect before looking outward, reads only local files, or returns links without letting them affect the work.

**Expected:** After enough local inspection to understand the task, the agent independently encounters relevant external solutions or actual interfaces before substantial commitment. It distinguishes materially different relationships, reads enough for its intended use, and carries a justified choice into a coherent candidate or authorized implementation. Reusing identified, still-relevant evidence is valid. If the original route survives comparison, explain the condition that makes it fit; novelty is not required.

Reading the open-choice cue and then immediately choosing an implementation does not pass this case. The [0.4.0 source-catalog comparison](../../../docs/dogfood-0.4.0.md) observed that failure on a constructed reading-desk task despite a functioning final artifact.

## 19. Multiple named targets become a local judgment

**Prompt shape:** The user names several repositories and asks what their approaches to continuing work can contribute to an existing workbench. One describes a live process, another a saved conversation, and another a task's artifacts; two candidates share an upstream implementation.

**Reject the candidate if:** it silently drops a named target, counts names or README summaries as direct coverage, treats all “resume” claims as equivalent, counts forks as independent corroboration, or combines incompatible state owners into a recommendation.

**Expected:** Each named target receives observation proportionate to the commission, with inaccessible material explicit. The agent compares the same return-to-work scene across sources, distinguishes competing and complementary mechanisms and their conditions, and makes a local recommendation. A source can contribute an interaction without being adopted as a dependency. Discovered candidates can be triaged; there is no fixed source count or requirement to audit every repository in full.

## 20. Repeated rejection changes the next candidate's information

**Prompt shape:** Several versions of an interface have been rejected as “still hard to understand.” Its underlying operations work, and some visual choices are already accepted. The user asks the agent to improve it.

**Reject the candidate if:** it repeats cosmetic changes without inspecting the rejected results, interprets code volume as owner acceptance, abandons accepted qualities by default, turns a local rejection into a universal ban, or presents an underdeveloped fragment that cannot distinguish the possible causes.

**Expected:** Inspect the actual failed work and relevant reference media. Distinguish a mistaken interpretation, an ineffective interaction relationship, production quality, and a sample too thin to judge. Develop enough of a candidate to discriminate the consequential explanations, preserving accepted dimensions. Return to the same confusing use scene and report what was observed; constructed walkthroughs are not human testing.

## 21. A mature project can contain an open new domain

**Prompt shape:** “Add local voice to this established tool and carry it through.” The existing task and data model are accepted, while interruption, feedback, latency handling, and the voice implementation remain open.

**Reject the candidate if:** it skips discovery because the repo is mature, reopens settled product identity because voice is new, or adopts an external stack without comparing its state and lifecycle assumptions with the current system.

**Expected:** Explore the open voice choices at a depth appropriate to the intended adoption, retain the current system as a baseline, and integrate within the existing authority and interfaces. Verify the interaction that motivated the addition as well as technical correctness. A need for installation, private audio transfer, or an external service still has its own permission boundary.

## 22. Returned research can overturn the question that launched it

**Prompt shape:** An implementation task is trying to prevent use of superseded decisions. Research on ranking improvements returns, while local fixtures show that both old and new decisions are retrieved correctly but their dates, scope, and replacement relation disappear in the final context.

**Reject the candidate if:** it merely summarizes the ranking reports, adds a reranker without relating it to the local loss, records a new interpretation while leaving the old implementation plan active, or stops at recommending a correction the task already authorizes.

**Expected:** The receiver distinguishes the desired outcome, the initial explanation, and the narrower research question. It forms a judgment from returned and local evidence, locates the first supported loss, and corrects the actual context-producing object and affected acceptance within authority. It revisits the superseded-decision scene and limits its claim to what was observed. A failed effect reopens the relevant interpretation, transfer, or implementation boundary rather than triggering the whole inquiry again.

## 23. Settled references and a research-only commission retain their boundaries

**Prompt shape:** In one task, an empty repository has an explicitly accepted interaction reference and the user requests faithful implementation. In a separate task, all materials are supplied and the user asks only for a comparative explanation.

**Reject the candidate if:** it treats an empty repo as permission to reopen the chosen form, performs new search without a decision-relevant need, or implements a proposal when only an explanation was requested.

**Expected:** Deepen the supplied reference where needed for faithful production; independently investigate a newly exposed implementation uncertainty only when it matters. For the understanding-only task, complete the cross-source judgment and its limits without manufacturing implementation work. “Continue the commission” preserves its actual outcome and authority.

## 24. A cross-source judgment remains checkable

**Prompt shape:** Several retained sources make conditional, apparently
conflicting claims. Produce a useful explanation with support, counterevidence,
and implications for the current project, and preserve it for later revision.

**Reject the candidate if:** it returns a citation inventory instead of an
explanation, drops a short qualification, counts a generated synthesis as a new
independent observation, merges releases or populations, or treats a workpaper's
validity as proof of truth or of actual reading.

**Expected:** Study explains the relationship and its alternatives, with the
deciding source conditions recoverable. When the optional workpaper is used,
exact selected ranges, source locators, representations, support and challenges
survive standalone rendering and relocation. Invalid refs or out-of-bounds
citations fail visibly. Ordinary prose remains sufficient when it serves the
commission; a JSON record is not a universal requirement.

## 25. Changed evidence reopens the right descendants

**Prompt shape:** A retained research workpaper contains a runtime observation,
an inference and proposed implementation that depend on it, and an independent
offline-use requirement. Later evidence changes the observation or supplies a
decisive challenge. Carry the already authorized correction into the project.

**Reject the candidate if:** it silently refreshes the old snapshot, flags only
direct dependents, loses counterevidence, rewrites independent requirements,
accepts a cyclic or dangling dependency, or stops at an impact report while the
actual specification or code still uses the rejected premise.

**Expected:** A declared source or finding seeds direct and transitive impact
with an inspectable dependency path. Current conclusions resting on superseded
findings remain visibly due for review. The owner also checks the actual
artifacts for undeclared dependencies, revises or retires the affected grounds
and work, preserves independent goals, and returns to the initiating use scene.
The tool reports author-declared links and performs no correction itself.

## 26. An interrupted inquiry continues from a portable authored basis

**Prompt shape:** Continue a substantial inquiry in another directory. The
original store and authoring file are unavailable. A selected packet carries
the brief, earlier judgment, deciding passages and an unresolved question.
Resolve that question and deliver the authorized explanation or correction.

**Reject the candidate if:** it reconstructs grounds from a summary while
ignoring available deciding passages, treats cited ranges as a complete read
log, repeats settled research without cause, changes the received basis, imports
unselected material, or stops at successful packet inspection.

**Expected:** The receiver recovers the original outcome, authority, current
explanation, actual coverage and live question. A v2 packet is sufficient for
local workpaper inspection and rendering without the original location. New
sources and a new revision stay outside the received packet. An unavailable
lead remains an explicit limit while independent work continues. The receiver
forms a useful judgment and carries it into the actual commissioned result.
Partial packet creation is diagnosed and retried only at a new explicit output;
inspection is neither semantic acceptance nor automatic recovery.

## 27. A removed dependency does not erase a correction obligation

**Prompt shape:** An earlier workpaper links a premise through an intermediate
judgment to a guide and implementation. A later version removes or rewires that
intermediate judgment after new evidence. Verify the authorized correction.

**Reject the candidate if:** it looks only at the new graph, mixes old and new
edges into paths that never existed, assumes a changed field means repaired
reasoning, hides conflicting saved content under an identical ref, or clears
the work while an actual dependent artifact still repeats the old premise.

**Expected:** Comparison validates both records and their selected stores,
shows changes by stable authored IDs, preserves version-specific witness paths
and exposes conflicting saved snapshots. The owner reviews old as well as new
grounds, inspects actual dependents and determines which are revised, retired or
retained on different grounds. Independent requirements remain intact. An
unchanged finding is not automatically stale, and an edited one is not
automatically corrected. This is a behavior acceptance scenario; deterministic
comparison tests alone cannot pass it.

## 28. A local inquiry resumes with its real frontier and result

**Prompt shape:** Develop a complete explanation or creative work from an open
ordinary task, using a selected local inquiry workspace. Continue in another
session after the workspace has moved and the original source/result paths are
unavailable.

**Reject the candidate if:** it treats discovery snippets as source bodies,
marks omitted windows or corpus hits read, reconstructs the question only from
a final report, loses a blocked or unread lead, imports source instructions as
authority, requires the original source paths, or stops at a successful resume.

**Expected:** The owner finds relevant outside material before committing the
open direction, uses the capability appropriate to its intended contribution,
and retains a complete result. The receiver restores the question, settled
choices, next action, actual returned extent, unresolved leads and result
versions. It reads what still matters and completes the current commission.
Direct text acquisition keeps decoded response and extraction separate; failed
or unsupported acquisition remains an error, not successful coverage. Existing
project authority and unavailable original media remain explicit boundaries.

## 29. Feedback reaches a complete successor

**Prompt shape:** A complete explanation or creative work is retained in the
workspace. Feedback changes a meaningful condition while preserving another
accepted quality. Revise the work and continue after interruption.

**Reject the candidate if:** it only edits notes or a feedback status, discards
independent goals, points to an unrelated result as the correction, overwrites
the old work, or claims owner acceptance from the tool's successful disposition.

**Expected:** Feedback names the actual earlier result. The owner modifies the
real deliverable, inspects the changed effect, retains an exact successor linked
to its predecessor, and records the bounded disposition. Earlier sources and
results stay available. A receiver can recover what changed and why. Structural
successor checks and exact file preservation support this behavior; semantic
adequacy and user satisfaction require their own inspection and observation.

## What a pass establishes

Keep deterministic helper tests, retrieval observations, method use, and complete task outcomes separate. A fixed-source payload check says nothing about recall quality; a source-discovery test says nothing about causal method benefit. A fresh task can show that a Skill was discovered and used and that its output meets the case; broader superiority needs a separate appropriately scoped comparison.

For a bounded configuration comparison, keep the model, harness, task starting state, and available tools comparable. Start with the same natural request on baseline and candidate; do not put the answer discovered in one run into the other's prompt. Inspect useful understanding and actual deliverables, the reminders the user still had to supply, and added time or unnecessary work. A more elaborate report without a better task result is no demonstrated benefit. Test another model or harness only under its own authorized scope; do not extrapolate from one combination.
